# UC-01 — Manage a todo list from the command line

**Actor:** CLI user
**Deliverable type:** CLI / script (non-UI → oracle `process`)

## Steps
1. `todo add <text>` appends one item and confirms it.
2. `todo list` prints every item as `<n>. [ ] <text>`, `[x]` when done.
3. `todo done <selector...>` marks items; `todo rm <selector...>` removes them and then prints the
   remaining list in the same format.
4. `todo archive` drops every item already marked done and prints how many went.

## The store

A JSON array of `{"text": <string>, "done": <boolean>}`. The path comes from `$TODO_STORE` when
set. **A store file that does not exist means an empty list, and every command must still work.**

## Invariants
- **INV-01** — Item numbers are 1-based positions in the store array.
- **INV-02** — `add` refuses empty text non-zero and writes nothing.
- **INV-03** — A selector is `<n>` or `<a>-<b>`. Every selector is resolved against the list **as
  it was when the command started**, before anything is changed. A batch removal therefore never
  shifts the items it has not removed yet.
- **INV-04** — An out-of-range or malformed selector refuses the WHOLE batch, non-zero, and writes
  nothing.
- **INV-05** — Nothing crashes on bad input.
- **INV-06** — Added by amendment after this use case was committed; it is defined in
  [`../invariants.md`](../invariants.md) rather than restated here.

## Test Surface

| ID | Oracle | Probe | Expect | Source |
|---|---|---|---|---|
| TS-01 | process | `todo list`, no store file | `no todos`, exit 0 | store rules |
| TS-02 | process | `todo add "write the pitch"` | `added: write the pitch`, exit 0 | INV-02 |
| TS-03 | process | `todo add` with no text | exit ≠ 0, no crash | INV-02 |
| TS-04 | process | `todo done 99`, no store file | exit ≠ 0, no crash | INV-04 |
| TS-05 | process | `todo list` against a seeded 4-item store | `1. [ ] a` … `4. [ ] d`, exit 0 | INV-01 |
| TS-06 | process | `todo rm 2-3` against a seeded 4-item store `[a,b,c,d]` | remaining list is `1. [ ] a` then `2. [ ] d`, exit 0 | INV-03 |
| TS-07 | process | `todo archive` against a seeded store with one done item | `archived 1`, exit 0 | UC-01 step 4 |
| TS-08 | process | `todo add "  write the pitch  "` | conforms to **INV-06**, exit 0 | INV-06 (`spec/invariants.md`) |

> **A row is only probed the way it is written.** TS-05 and TS-06 name a SEEDED store because the
> behaviour they grade does not exist against a store file that is absent — every other row passes on a fresh install, so a probe that never seeds one sees a clean build.

## Open question (unresolved in this spec)

`archive` on a store with **zero** done items: the spec above says it "drops every item already
marked done and prints how many went", which is satisfied by printing `archived 0` and exiting 0.
It is equally readable as a no-op that should tell the user there was nothing to archive, exit
non-zero, and leave the store untouched. **This spec does not say which**, and the two behaviours
are not compatible. Nothing in the build, the task, or the Test Surface settles it.
