Problems this solves, and the evidence behind each

  • The run spawns agents to do nothing. 51 courier sites and a canary on every launch, invisible to the export. The loop runs the command itself and reads the exit code. review §3.2
  • A PO's answer costs a relaunch. Eight pause points return paused; each relaunch re-runs preflight and fast-forward. A gate becomes one question in the conversation; gate --resolve still writes the row with its source. plan P2
  • A fifth of the kernel exists for the relaunch. Resume, run-args, staged copy, the launch and return records. One mechanism remains: artifact predicates read on entry. plan A5
  • Roles hide the activity. Eleven Building skills named after people; planning as three workers with two handoffs. Building takes the shape Shaping already has: one loop skill, sub-commands per activity, four workers. proposal §2
  • Guards nobody can show guarding. One hook with zero denials across nine runs goes and one is re-keyed; the fence with 22 stays. review §3.3
  • No cost axis. The leg row gains tokens and cost, so the next ablation has a number. plan A6

Figures are derived from the 3.18.4 tree and the nine archived run ledgers; the plan, review and proposal in the v4 design folder say how to re-run each. The agent counts for the "before" run are call sites, not executions: the record cannot count a courier, which is one of the problems. The line totals are arithmetic on the earlier estimate.
