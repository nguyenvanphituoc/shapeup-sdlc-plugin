Anatomy of a constrained agent runtime

Thirteen skills, eleven hooks and eighteen scripts arranged around one idea: an agent's word is never load-bearing. This document draws the machine, then explains why each skill's own definition forces the mechanism attached to it.

Scope hooks · pipeline scripts · envelope schemas · skill contracts Suite 803 structural checks, passing Plates six
§1
Thesis

Claims versus facts

Every agent harness has to answer one question: when the model says it finished, on what basis do you believe it? Most answer with better prompting. This one answers by removing the model from the sentence.

A worker here never writes to the board, the ledger, or the verdict file. It returns a JSON WorkResult — a proposal — and a script applies it. Whether the run started is a receipt on disk. Whether the tests pass is the exit code of a process that actually ran them. Whether a scope improved is a comparison between two score vectors. The model contributes craft; the runtime contributes every fact anyone downstream relies on.

The gate is not a paragraph asking the model to stop. It is a PreToolUse hook returning permissionDecision: "deny", and the tool call never happens.

That distinction produces the three planes in Plate 1. Read them as a cost gradient as much as an architecture: the two lower planes are deterministic Node processes costing zero model tokens, and the one plane where the model reasons freely is also the only plane whose output is treated as untrusted.

Four denial points and one advisory, each closing a failure that was measured rather than imagined. gate-intake exists because a benchmark hand-off dropped the requirement text and kept the flags. gate-zerowork exists because an orchestrator once printed its own pipeline in future tense and stopped — scoring 29% while reading like a clean run.

Plate 3

The envelope port

Steps 3–5 are context engineering, not bookkeeping. The worker gets facts and no transcript: eight compacted trial rows ≈ 600 tokens against an attempt budget of five. Crossing the round boundary is deliberate — a fix round that starts blind to the build round is how the same failed change gets proposed twice.

§5
Plate 4

The ratchet and its pawl

Most agent retry loops are memoryless: N attempts, each starting from whatever mess the last one left. This loop scores every attempt as a vector and keeps the tree only when the score strictly improves. A tie is not better — a tie that counted as improvement would make a sawtooth look like a ratchet.

score = { regressions ↓ , fixtures_passed ↑ , fixtures_total , db_probe ↑ }

better(next, current)
  current == null              → true    baseline, first trial
  fixtures_total differs       → null    incomparable — a split changed the denominator
  regressions differ           → fewer wins        (a regression is never an improvement)
  fixtures_passed differs      → more wins
  otherwise                    → false   a tie is not better

Trial 3 is the whole point: red, but better. Under a pass/fail loop it is indistinguishable from trial 2 and both get discarded. Under the ratchet it becomes the new floor, and attempt 4 starts from working code instead of from an unexplained tree. Each row appends to t0/trials.jsonl carrying baseline_trial — a parent pointer that makes the attempt history a DAG with no graph store behind it.

§6
Plate 5

The enforcement layer

Eleven registrations, four events. Every one of them fails open when it cannot prove a violation — a gate that breaks legitimate runs gets disabled, and a disabled gate enforces nothing. What makes fail-open auditable rather than invisible is the receipt: since v1.5 every hook appends a decision row, so inspected-and-permitted, no rule matched, threw, and never ran are four distinguishable facts instead of one silent exit 0.

Plate 6

Where state lives, and who may write it

§8
Definitions

Why each skill needs its mechanism

Every skill in this harness declares a boundary in its own definition — usually in the form "NOT for X", "pure worker", "the single judge", "sole writer". Those clauses are the interesting part, because a boundary stated in prose is a boundary the model can reason its way across. Each one therefore generates a specific runtime obligation. Read the cards as: what the definition promises → what would break it → what makes it true.

The four that carry the load

/tech-lead — the orchestrator
"The evaluator runs exactly once per build round, only after the board is 100% done. Never per task. The tech lead is the only component that can enforce this, because no sub-skill sees the whole board."
What breaks itAn orchestrator that is also the thing being orchestrated can always re-decide the timing. Under budget pressure "once per round" drifts to "once per task", and a per-task PASS is not evidence about a feature.
gate-l2.mjs reads the board from two independent sources — task frontmatter and the index table — and denies the EVAL dispatch while either shows unfinished work. The rule leaves the prompt entirely.
/spec-evaluator — the judge
"The single judge… skeptical by default — absence of evidence is a FAIL. payload.t0_artifacts[]: an artifact listed but missing or red on disk → the round is NOT gradeable."
What breaks itA judge grading from the same context that produced the work. "Skeptical by default" is a disposition, and dispositions bend — especially when the alternative is reporting failure at the end of a long run.
t0-verify.mjs writes an immutable verdict artifact (flag:"wx", never clobbered) that the judge must cite by path and sha256 it re-computes itself. No agent can fabricate the contents, because a process produced them by running commands.
/task-executor — the generator
"Zero-memory, substrate-sandboxed… substrate.allowed is the ONLY globs you may write. A needed file outside them → ESCALATE, never a write (a sandbox hook blocks it anyway)."
What breaks itParallel scopes. Two executors both convinced they own src/store.ts, one silently overwriting the other's completions — with both reporting done, truthfully, from their own point of view.
sandbox-guard.mjs intercepts every Edit/Write and denies paths outside the contract's whitelist. The parenthetical in the definition — "a sandbox hook blocks it anyway" — is the skill acknowledging that its own instruction is not the enforcement.
/qa-edge-hunter — the explorer
"Return each finding… always ~. Does NOT render a verdict, score, or PASS/FAIL of any kind. QA is a level-up, not a gate."
What breaks itA second grader. If QA can block, the harness has two judges disagreeing at ship time and no rule for which one wins — and the cheapest resolution is always "ship nothing".
The marker is structural, not stylistic: discoveries[] has no verdict field to populate, and promotion from ~ to must-have happens only at GATE H, by scope-hammer with PO confirmation. The Stop hooks that could block deliberately don't — anti-rationalization emits systemMessage and never decision:"block".

The planners — why "sole writer" needs a script

/scope-architect
"Writes the committed scopes/*.md contracts… NOT for decomposing a pitch into tasks (ba-pitch-analyzer) or cutting scope at ship time (scope-hammer)."
What breaks itThree skills all plausibly "about scope". Any of them could write the contract; if two do, the substrate whitelist the sandbox hook reads has two versions.
compile-order's substrateFor() issues a different write whitelist per operation. map-scopes may write scopes/*.md; generate-board has that path listed as frozen. Role separation becomes a filesystem fact.
/solution-architect
"The wiring map that guarantees no engine ships orphaned… engine → integration seam → composition-root attachment → player-visible affordance."
What breaks itThe failure it names: 631 lines, 26 passing tests, zero call sites. Every test green, the feature absent from the running app. No amount of unit testing detects this, because unit tests import the module directly.
trace-lint.mjs BFS's the real import graph from the profile's entry_point and reports any use-case engine with zero import sites. Profile-gated, never hardcoded — main.js for a game is not the seam for a web service.
/ba-pitch-analyzer
"Five order-selected operations… the coverage op writes the SHARED requirement registry for covers-closure."
What breaks itThe dropped clause. A customer requirement that silently vanishes between the pitch and the board — not contradicted, just gone, so nothing downstream has anything to disagree with.
trace-lint's covers-closure arm: every REQ marked covered must be named by at least one acceptance criterion's (covers: REQ-n) clause. Uncovered and not CUT is red. And spec-lint.mjs grades the planner's own output, because a worker auditing itself was always a judge-purity smell.
/orient — the scout
"Pure worker (the harness rule: stateless workers, one stateful orchestrator). It receives run metadata as arguments; it never reads or writes a shared run-state file."
What breaks itAny worker that reads shared state also depends on its format — and then moving a directory breaks five skills instead of one script.
The WorkOrder is the entire dependency surface. Path resolution, run-state parsing and board globbing all moved into compile-order.mjs, so a topology change touches one file and zero skills.

The governors — budget, escalation, learning

/scope-hammer
"Compares the product to the pitch's baseline — what customers live with today, not a perfect ideal."
What breaks itComparison against the ideal, which makes every incomplete run look like a failure and encourages one more round instead of shipping the green part.
All three stop conditions route here rather than to an exit: normal completion, round budget, and attempt budget (queued as a hammer_proposal that never blocks the round). gate-deadline.mjs deliberately refuses to deny scope-hammer — a breaker that also blocked the exit would strand green work.
/coach
"Three workers have a read-side hook; they are the complete set of categories the gate may offer. spec-evaluator is deliberately excluded."
What breaks itFeedback filed against the judge. The KB is guidance; routed into the evaluator it becomes an invariant, and the single-judge rule quietly gains a second grader made of accumulated opinions.
compile-order attaches payload.kb_rules_path from a hard-coded three-entry map — executor, planner, hunter. There is no path by which a rule reaches the judge, and GATE COACH-1 asks the PO which skill owns each rule rather than assuming.
/translator · /shapeup
"The single language gate… original never overwritten." · "Shaping, Betting and Kick-off are PO-personal and upstream: intake is a kicked-off pitch, never a raw idea."
What breaks itBuilding from an unshaped idea, or from a translation whose source is gone. Both produce work that cannot be traced back to anything a human agreed to.
init-run.mjs hashes the intake into the receipt and writes it verbatim to intake.md. "The spec was dropped on the hand-off" stops being arguable and becomes checkable — which is exactly how that hypothesis was falsified the first time it was raised.
Read as a set, the pattern is consistent: wherever a definition says only, never, or exactly once, there is a script or a hook standing behind it. Where there isn't one, the clause is decoration.
§9
Findings

Six findings, five closed

Applying that last test to the tree turned up six places where a definition promised more than the runtime delivered. Five have since been fixed; one was resolved by deciding it was not a defect. The record is kept because how they were closed is the more useful half.

Closed — 1 · The sandbox guard was armed by a prompt

init-run.mjs wrote active-scope without scope_id, and sandbox-guard fails open without it — so the substrate whitelist stayed inert until a model remembered a runbook line. Every generated path now resolves through lib/paths.mjs, and structural test #45 asserts no runtime file names a storage root anywhere else. It caught seven sites a grep had missed on its first run.

Closed — 3 · The board checkbox matcher

Bidirectional substring matching meant "user can log in" could tick the box belonging to "user can log in with SSO". Fixed alongside the contract work, with the round-trip pinned by test #46.

Closed — 4 · The Skill / Agent asymmetry

GATE L2 matched only Skill while validate-envelope matched both. Moot now: L2 is advisory (ADR-0001), and the denial that matters — validate-envelope — always covered both paths.

Closed — 5 · Trial ordinals, and 6 · the unconditional first keep

Both were about the ratchet describing a tree nobody has. The ship report now reports the last kept trial rather than the last trial, and test #47 pins exactly that: a fixture where attempt 2 reached 5/5 and attempt 3 regressed to 4/5 and was reverted must report 5/5.

Open — 2 · git stash create does not include untracked files

The ratchet's snapshot header claims it does. Verified: it does not. The commonest executor output is a new file, so snapshot() never captures it and restore() neither restores nor removes it — a reverted trial reports a revert that largely did not happen.

Still open because the fix is a behaviour change, not a correction: making the snapshot include untracked files means a revert can now delete a file the harness cannot prove it created, and that trade belongs to the PO.

The instructive part is that all six were the same defect the project exists to catch, one level up: a mechanism whose failure signature is identical to its success signature. A guard that fails open silently, a revert that partly happens, a tick that lands on the wrong line. The tools for finding that shape in a model's work were excellent; they had not been turned on the harness itself. Tests #45–#47 are that turn.
