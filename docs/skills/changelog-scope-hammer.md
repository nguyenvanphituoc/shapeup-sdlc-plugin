# Changelog for scope-hammer

| Version | Date | Changes |
|---------|------|---------|
| retired | 2026-11-07 | **Folded into the loop's `stop` step; the skill, its `hammer` operation and its worker role are gone.** The census, the baseline comparison (never the ideal) and the cut list are now done by the `building` loop in its own context, as the `kind: stop` step `probe next` hands out; the craft and every hard rule moved to `skills/building/resources/stop.md`. Every ownership, exhaustion and requirement claim still cites `probe owner`, `probe attempts` and `probe requirements` — the step carries the exact commands. The census file keeps its name and shape (`reports/hammer-census.json`, `schema_version` 1) because GATE L4's resolver reads that file and nothing else; the kernel now checks it against that shape (`reduce ingest --close-census`) and a census it refuses is sent back once, then stops the run. `/hammer` keeps its name and routes to the `stop` sub-command. |
| 0.3 | 2026-08-02 | **ADR-0001 consumer layout** (unreleased). The baseline the H1 comparison resolves against moves with the shared root — `shapeup/<slug>/shaping/baseline.md` (was `docs/shapeup-sdlc/…`); the same rename applies to the standalone `--baseline` flag. Census, baseline-not-ideal comparison, cut list and the three triggers (normal stop, outer breaker, inner per-scope breaker) are unchanged. The hammer's inbox grows one row type in v1.5: a scope can now reach GATE H through the **stagnation** term of the inner breaker (`no_progress_k` consecutive non-`kept` trials) as well as through an exhausted `attempt_budget` — the proposal shape it queues is identical, so nothing here changed. Earlier (2026-07-24): description reflowed, no trigger words added or removed. |
| 0.2 | 2026-07-14 | **Domain-layer alignment.** Documented the envelope contract: orchestrated dispatch is WorkOrder in (`--order`) / WorkResult out like every worker; standalone flags map 1:1 onto the payload fields registered in the central domain registry (`domain.schema.json` `x-payload-by-worker`), and output fields follow `x-result-by-worker`. No behavior change. |
| 0.1 | 2026-07-12 | Initial release (design spec v1.1 step 11 / DD-9 / Blueprint A `hammer_proposals`). GATE H0 census (scopes + QA + discovered + advisor-overflow) → GATE H1 baseline comparison (never vs. a perfect ideal) → GATE H2 cut list + verdict, PO-confirmed. Handles all three triggers: normal stop, outer breaker, inner (per-scope) breaker. |
