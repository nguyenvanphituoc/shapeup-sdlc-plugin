# Changelog for task-executor

| Version | Date | Changes |
|---------|------|---------|
| 2.3 | 2026-08-09 | **The v2.2 gap is closed, and the class of gap is now a build failure.** `payload.trial_history[]` is declared in the input-contract table: reverted rows are changes already tried and already worse (do not re-propose), a `kept` row with a still-red score is the tree you are building ON. Before this, the tree ratcheted mechanically — git restored it whether or not anyone read anything — while the reasoning ratcheted only if the worker happened to read an undeclared field. The generalisation matters more than the row: `tests/structural/50-payload-contract-parity.mjs` now asserts every field `x-payload-by-worker` registers appears as `payload.<field>` in that worker's own SKILL.md, closing the third edge of a triangle whose other two (§24 registry↔schema, §21 producer↔schema) were already enforced. It found two more instances on its first run — `orient` (`spec_folder`, `feature`) and `qa-edge-hunter` (`ledger`) — both now declared. |
| 2.2 | 2026-08-02 | **ADR-0001 consumer layout, and the loop around this skill becomes a ratchet** (unreleased). Paths: orders and results are `.shapeup/<slug>/…`, the spec is `shapeup/<slug>/spec/`, and the standalone shim derives `<slug>` from the new shared root. Every script path the skill prints is the fully-qualified `${CLAUDE_PLUGIN_ROOT}/skills/tech-lead/scripts/…` form — the bare `node scripts/…` form resolved to nothing from the project cwd and matched no `permissions.allow` rule, measured at 26 approval denials in one session. **What actually changes for the worker is the handoff**: `t0-verify` now scores each attempt and either *keeps* it (snapshotting the tree) or *reverts* it, so attempt N+1 builds on attempt N's kept tree instead of on whatever the last attempt left behind, and a red-but-improved attempt (2/5 → 4/5 fixtures) is kept rather than discarded. Orders gain `payload.trial_history` — up to 8 prior trials with score, status and top-3 digest, **crossing the round boundary** — where the zero-memory handoff previously carried only the last attempt's `digested_errors`. Still facts only, still no chat history (PA6). **Gap:** `trial_history` is registered for this worker in `domain.schema.json` and compiled into its orders, but the payload table in `SKILL.md` documents only `digested_errors` — the worker is handed a field its own contract never tells it to read. |
| 2.1 | 2026-07-24 | **Description compressed** (skills-optimization). The `>` block scalar became one quoted line and dropped the envelope recital ("Input: a WorkOrder envelope. Output: code + a WorkResult envelope… never writes run-state, task boards, indexes, or ledgers") in favour of trigger phrases plus the one-line craft statement. Nothing weakened: the pure-worker rules are body content and hook-enforced (`sandbox-guard`, single-writer `ingest-result`), not description content. |
| 2.0 | 2026-07-13 | **Pure-skill rewrite** (pure-skill architecture plan, P2): the skill is now craft-only — WorkOrder in, code + WorkResult out. Deleted: GATE A (locate/validate), GATE B1–B4 (dependency/env plumbing — sequencing is the orchestrator's job, the test command arrives in the order), Phase 3 doc-update fan-out (P3.1–P3.6 → `ingest-result.mjs`), GATE E sign-off (the orchestrator's gate), all standalone-vs-brief mode branching, and the `--brief` format itself. Kept verbatim as craft: the PLAN assumptions/observable-criteria step (old GATE C), Karpathy minimum-code/surgical rules (P2.7/P2.8), UI Layer 1/2/3 discipline, contract-reference rule, Non-Go stop, SPIKE decision-doc mode, the ESCALATE protocol, and the zero-memory rule. New: anti-rationalization table + closing verification checklist (agent-skills anatomy); AC evidence now returns as `ac_results[]` data with verbatim checkbox text. Standalone `--spec/--task/--next` preserved via a 10-line preamble shim over `compile-order.mjs`. 580 → ~250 lines. |
| 1.x | 2026-06/07 | Gate-pipeline versions (GATE A–E, isolated-brief mode, substrate discipline, UI layers). Superseded by the pure-worker contract; see git history for details. |
