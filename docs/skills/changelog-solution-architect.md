| 1.1 | 2026-07-24 | **Design-intent reframe** — the skill runs at design time (GATE L1a.5, before any code exists) but was written as a build-time *verifier*, and that mismatch produced two defects. **(a) Fabricated coordinates:** it taught the worker to emit `entry_call_site: "main.js:42"` — a file:line for code that does not exist yet, and one parsed by nobody (trace-lint's reachability is an import-graph BFS from `ProjectProfile.entry_point` to `engine`; the Mermaid view reads `use_case`/`engine`/`affordance`; the slicer reads `wiring_seam`). `entry_call_site` is now **design intent**: the symbolic composition-root attachment named from the profile's `entry_point` + mechanism (`"src/server.ts — POST /checkout route"`), never an invented line — the concrete coordinate is a build-time fact. `domain.schema.json`'s field description was updated to match. **(b) Layer inversion:** Core-process step 4 made a pipeline-blind worker run the orchestrator-owned `trace-lint.mjs` as mandatory craft — removed. The oracle stays the orchestrator's, run advisory at L1b (the same rule that keeps `t0-verify.mjs` out of task-executor); the standalone preview moved to the Invocation block, labelled near-vacuous pre-build. Craft restated as the real architect job: engine assignment → integration-seam mechanism → composition-root attachment → affordance, with an unattachable engine surfaced via `deviations[]`/`escalates[]` instead of a code-traced red. Anti-rationalization rows retargeted (`main.js:42` fabrication; "I'll run trace-lint to check my map"). No schema-required field changed — `WiringEntry` still requires only `use_case` + `engine` — so trace-lint and the spine fixtures are untouched. |
