shapeup-sdlc · ADR-0001 + ADR-0002

Two trees

A harness has two file layouts, and they answer different questions. The plugin's own repository asks when does this run? The workspace it generates in your project asks who is this for? Getting either wrong is silent.

Plugin 12 skills · 12 hook registrations · 6 oracles · 16 scripts Suite 880+ checks Tarball 139 files
§1
Principle

One axis per tree

Both layouts used to sort by kind of file — scripts here, docs there, tests over there. That is the arrangement that hides things, because "script" describes a file's syntax and nothing about its obligations. A shell script published as a curl URL and a shell script a maintainer runs once are the same kind of file and opposite kinds of commitment.

Sort the plugin by when it runs. Sort the workspace by who reads it. Neither tree needs a comment to be legible after that.

The two questions produce two different vocabularies, which is the point — you can tell at a glance which tree you are looking at.

§3
Boundary

The publish boundary was wrong three ways

A files[] array maintained by hand is the same class of thing this project refuses everywhere else: an invariant living somewhere nobody checks. It was wrong in both directions simultaneously.

EntryWasNow
agents/declared, and does not existremoved
dist/antigravity/declared, gitignored, 0 tracked files — the tarball depended on whether the publisher had run distribute.js locallyremoved; dist/ is build output, not product
skills/**/evals/**13 datasets shipped, while evals/README.md calls them "repo-only, not shipped"excluded — intent and mechanism now agree
oracles/absent — the quickstart told users to run a file no install containedships
The frozen directory

docs/upgrading.md publishes curl .../main/scripts/migrate.sh | bash. A curl | bash URL is a public API with no deprecation channel — rename the file and every published upgrade command 404s, silently for the reader and permanently for the search result that sent them there. That guarantee now lives in scripts/FROZEN.md, inside the directory it protects, rather than only in a doc the person tidying will not open.

Plate 2

The workspace it generates

Different question entirely. Nothing here is about lifecycle — it is about who reads the file. The rule is one line:

prose is the team's        →  shapeup/     committed
structured data is the machine's  →  .shapeup/    gitignored

The harness runs only on the machine that invoked it. A teammate reads the design; they never resume someone else's run. That single fact decides every row below.

Two exceptions, named

A rule with unnamed exceptions is a rule nobody can apply. These are the complete set — each breaks the prose/structured line, and each has a reason that is not "it was convenient".

The contract format

The first exception needed a format that is readable and parseable with no dependency. Frontmatter carries the scalars and lists; a markdown table carries the one array-of-objects field; prose carries the rationale.

That is what made the change safe: the envelope, its schema and validate-envelope are untouched. readContract() still accepts the legacy .json, so a project that upgrades its plugin and its data at different moments is never caught between them.

Plate 4

What a teammate actually sees

The split is by time, not by artifact. Everything a reviewer wants mutates throughout a run, so committing it live would churn the deliverable on every attempt. It stays local while it changes; its conclusions are frozen once.

Every figure in the report is derived — a reduce over artifacts the harness already wrote. Nothing in it is a claim the orchestrator makes about its own run, which would be the "agent reports done" pathology wearing a deliverable's clothes. One detail carries most of the honesty: the T0 table reports the last kept trial, not the last trial, because a reverted trial's tree was thrown away and reporting its score would describe code nobody can see.

§7
Guard

Why the rename was survivable

Both roots were hard-coded in about ninety files, in two syntaxes — 568 string literals and 48 sites that built the path from join() segments. A find-and-replace catches the first set and silently misses the second, and the result throws no error: the script reads a directory that is not there and takes its fail-open branch.

So the roots got one home before anything moved.

skills/tech-lead/scripts/lib/paths.mjs

  export const SHARED = "shapeup";    ← renaming a root is this line
  export const LOCAL  = ".shapeup";   ← and this one

tests/structural/45-paths.mjs
  asserts no runtime file names a storage root outside paths.mjs,
  in EITHER syntax — mirroring test #11a's guard on the main-guard bug

The test earned its place immediately: it caught seven sites the grep had missed, all user-facing message strings with the root name baked in. Extracting first and renaming second also meant every failure after the flip was provably a fixture, not a refactor bug.

This is the third time this repo has fixed the same shape — a duplicated fragile thing, given one home, with a test that no file may bypass. is-main.mjs, then argv.mjs, now paths.mjs.
