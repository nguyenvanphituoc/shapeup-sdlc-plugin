# Part A — the mechanism

## M0. Why this came first

The paper's five planes — control (`tech-lead`), execution (workers + hooks), artifact (files),
evaluation (`spec-evaluator` + `t0-verify`) — were all present. The ontology, the expensive part,
already existed as `domain.schema.json` (38 `$defs`, an `x-erd` block declaring 30 typed
relationships with cardinality and named join keys), hook-validated in both directions.

Two facts blocked everything downstream, and neither was fixed by adding a plane:

| # | Fact | Verified at |
|---|---|---|
| 1 | **No comparison existed.** `better` appeared nowhere except one comment. `computeVerdict` returned four booleans; N fixture outcomes collapsed through a single AND. | `t0-verify.mjs` |
| 2 | **History was one attempt deep, and self-destructing.** The only prior-attempt data reaching a worker was one file's error digest; the verdict artifact was written with a bare `writeFileSync` under a protocol that retries the same attempt number. | `compile-order.mjs`, `t0-verify.mjs` |

Fact 2 is invariant **I4** — *"every superseded object remains addressable"* — the one the roadmap
names as most clearly violated. Only two files in the codebase used `appendFileSync`.

**The sequencing consequence.** Any roadmap phase that begins *"compute these statistics over three
past boards"* has an undeclared prerequisite: `.shapeup/` is gitignored and the verdict artifacts
overwrote each other, so those measurements could not be taken from data the system retained.
This work was that prerequisite.

## M1. The tier decision

One question decides where every new file lives:

> If I `rm -rf .shapeup/` and a teammate clones fresh, must this file still exist and still mean the
> same thing? **Yes → SHARED** (`shapeup/`). **No → LOCAL** (`.shapeup/`, gitignored).

| Artifact | Tier | Location |
|---|---|---|
| **Trial ledger** — one row per T0 run: score, status, parent | LOCAL | `.shapeup/<slug>/t0/trials.jsonl` |
| **Verdict artifacts** (re-addressed, no longer clobbering) | LOCAL | `.shapeup/<slug>/t0/verdicts/r<R>-a<A>-t<T>.json` |
| **Decision receipts** — one row per hook evaluation | LOCAL | `.shapeup/decisions.jsonl` — checkout-wide, because hooks fire outside any run |
| **Ratchet + hook aggregates** | SHARED | the committed metrics harvest |
| **Kept-tree snapshots** | LOCAL (git) | `refs/shapeup/<scope_id>/kept` — shadow refs, never commits on the user's branch |

The aggregates being SHARED is load-bearing: both exit criteria are measurements that only become
meaningful across runs and across machines.

## M2. Day 1's mechanism — the pawl

The paper's template is `ratchet_loop(inspect, propose, apply, evaluate, keep, revert, better,
baseline)`. Six of eight positions were filled and filled well. `better` and the `Trial` history
were absent, and they are the two that make it a ratchet rather than a budgeted retry loop.

```js
/** The comparable T0 outcome. A vector, not a float — the three arms are not fungible. */
export function score({ fixtures, dbProbe, seesaw }) { … }

/** The pawl. Lexicographic, strict.
 *  @returns {boolean|null} true = strictly better · false = not better · null = incomparable */
export function better(next, current) { … }
```

Both live in `skills/tech-lead/scripts/t0-verify.mjs`. `null` for *incomparable* is the load-bearing
case: when `fixtures_total` changes the contract changed, and two scores measure different
instruments — the same rule the measurement half applies to a fixture fingerprint (§4, P3).

Four consequences, each now real in the code: verdict artifacts are addressed
`r<R>-a<A>-t<T>` so a retry no longer overwrites its predecessor (I4); `trials.jsonl` is
append-only with `baseline_trial` as the parent link; `keep`/`revert` is one rule instead of two
branches, and a **red-but-improved** attempt is kept — that is the whole ratchet, and it visibly
changes build behaviour, so it was flagged as a decision rather than slipped in; and
`compile-order` widens `inspect()` by putting a token-bounded `trial_history` in the WorkOrder.

## M3. Day 2's mechanism — the three legs

The paper's tool contract is **typed schema · permissions · result confirmation**, and the three
fail separately, so each has its own leg and its own structural section:

| Leg | What it does | Pinned by |
|---|---|---|
| 1 — type the argv boundary | `lib/argv.mjs`; a malformed flag is rejected before anything runs, exit 2, nothing written | structural §42 |
| 2 — make the grant match the prose | every documented invocation is in the literal form the permission grant matches | structural §43 |
| 3 — give `allow` a receipt | `hooks/lib/decision.mjs`; every hook records allow, deny **and error** distinctly | structural §44 |

Leg 3 is the one that repays. Audit **F-16** found **26 enforcement points silently inert behind
610 green structural checks** — and a guard that never fired and a guard that was never written are
the same guard from the outside. Result confirmation is exactly the discipline that separates them,
and it was the one requirement nothing in the repo recorded.

## M5. Non-goals

| Not doing | Why |
|---|---|
| **A graph store / graph plane** | The paper's own §VIII.C: do not introduce a graph because the system has agents. Exactly one workload here has a graph-shaped need — `session-rehydrate`, which fires 3/3 and recovers 0/3 because it hands a *pointer* where a context builder should hand *state*. Build the store when that is built, not before. |
| **Parallel dispatch** | Capped at ~3.3× with six human gates at 30 min. Human gates are this product's thesis. Scope it to `--unattended` or cancel it. |
| **Entity resolution** | The commit DAG and the knowledge graph should not be collapsed. This system needs the work-lineage half. Canonical ids over `entities: [Order, LineItem, Payment]` import a catastrophic-false-merge risk to answer queries nobody has asked. |
| **Any change to gate semantics or the envelope port** | Both work. This added a field to the order and an exit path to the hooks; it moved no boundary. |
| **Making `spec-evaluator` coachable** | Architecturally forbidden — the single-judge rule. |

## M6. Non-regression

Every new arm is skipped when its artifact is absent, per the existing ✦/✚ convention:

- `trials.jsonl` missing ⇒ `compile-order` falls back to the single-file read.
- `refs/shapeup/<scope>/kept` missing ⇒ no restore is attempted.
- `decisions.jsonl` unwritable ⇒ hooks still exit 0. The receipt is best-effort **by design**: a
  receipt that can break a run would get the whole layer disabled.
- Old `r<R>-a<A>.json` artifacts stay readable; `nextTrialNo` treats an unsuffixed file as `t0`.

# Part B — the measurement

> Section numbers **§0–§7 below are stable anchors**. `evals/README.md`, `evals/oracles/lint-rows.mjs`,
> the committed baseline and two rubrics cite them by number; renumber only with those citations.

- **Item:** make each skill's test work **measurable** on §VI.A's terms — a stored first draft, an
  evaluator with explicit criteria, a revision step, a stopping rule, every artifact stored — for
  the skills that can carry that measurement honestly.
- **Exit criterion (Table II):** a **measured quality improvement**. Operationally:
  `final_score ≥ approve_at` in a majority of runs, **on a fixture whose every graded row is
  derivable from the spec the skill was given.**
- **Scope:** Tier 1 — the five skills born measurable because a deterministic script already grades
  their artifact. Tier 2 (`translator`) and Tier 3 are out; see §6.
- **State: complete.** All five meet all four conditions of §1 under the condition-4 text as
  **amended by the operator on 2026-08-04**. Three meet it by a *demonstrated* revision —
  `scope-architect` (1 in 10, a four-round chain), `solution-architect` (1 in 3, reproduced across
  five instrument versions), `ba-pitch-analyzer` (1 in 16 pooled). Two meet it by a *resolved* rate:
  `task-executor` and `spec-evaluator` show zero revisions in 13 pooled runs each, bounding their
  rate at **≤21%**.
- **Under the ORIGINAL condition-4 text it is 3 of 5**, preserved in §1 with the amendment's
  rationale, its threshold derivation, and the fact that it makes all five pass.
- **The real finding is that condition 4 was never a property of the skills alone — it was a
  property of `n`.** Measured at n=3 it read three skills, then one, then two, with nothing about
  any skill changing in between.
- **The most valuable output is still not a score.** The loop found **five production defects** —
  all one family, the committed contract format failing silent — and each first appeared as a skill
  scoring badly.

## §0. The organizing principle

**The oracle is the rubric.**

The `spec-evaluator` pilot needed 9 hand-authored criteria, and that authorship was the source of
every problem it had: a rubric derived from the skill's own contract measures *contract
conformance*, ceilings at 1.0, and inherits the author's blind spots. Every Tier-1 skill is sole
writer of a committed artifact that a deterministic script already grades, so the rubric stops being
a judgement and becomes a **lookup**.

**Where the plan was wrong, and the error is instructive.** Zero authored criteria is reachable when
the oracle *runs the artifact*. It is **not** reachable when the oracle is a LINT, because a lint
reports findings and "no finding" is ambiguous between *checked and clean* and *nothing to check*.
Every authored row is one of exactly two kinds — a non-emptiness guard, or a coverage guard — and
both are forced: without them an empty `scopes/` directory scores 3 of 3 on the delegated rules, and
the score climbs with every rule delegated.

**The correction Phase 1 forced, and it governs every fixture:**

> **Every graded row must be derivable from the artifact the skill was given.** If a row can only be
> passed by inferring how the harness runs its probe, it is measuring the harness. Delegating to an
> oracle removes the *author's* blind spots; it does not remove the *apparatus's*.

The check is mechanical and costs nothing: for each row, name the line of the spec that requires it.
A row with no such line is either cut, or the requirement is added to the spec before measuring.

## §1. Definition of done

A skill counts as **done for this rung** when all four hold:

1. a rubric exists whose criteria delegate to an existing oracle wherever one can answer;
2. `--selftest` shows **weak < partial < strong**, and the partial fixture is committed;
3. a `--measure` run reaches `approve` in a majority of runs;
4. **the loop's revision behaviour is *demonstrated or resolved*** — either at least one measured
   run needed more than one round, or **zero did across `n ≥ 10` runs of one unchanged
   instrument**, with the resulting upper bound published — and every graded row traces to a spec
   line.

Condition 4 is the one that is easy to skip and the only one that makes 1–3 mean anything. A loop
that approves on the first draft in every run is a pass/fail check wearing a loop's clothes; a loop
that iterates toward the apparatus is worse, because it looks like learning.

> ### Condition 4 was amended on 2026-08-04, by the operator, after the results were known
>
> **The original text:** *"at least one run needed more than one round"*. **It read 3 of 5.**
> Both readings are preserved here on purpose, and a reader who prefers the original should use it.
>
> **Why it changed.** As written it is an *existence claim over a sample*, so its answer moves with
> `n` and with luck while the skill holds still. `ba-pitch-analyzer`'s verdict flipped **three times
> on a fixture that never changed a byte** — MET, then not met, then MET. A criterion a reader
> cannot reproduce from the same instrument is measuring the draw, not the loop.
>
> **Where `n ≥ 10` comes from, and it is not from the data.** A skill whose true revision rate is
> 1/3 is detected with ≥95% probability once `1-(2/3)ⁿ ≥ 0.95`, i.e. **n ≥ 8**. Ten clears that with
> margin. The threshold references a power requirement and no measured value; `RESOLVED_N` is
> exported and structural §48 fails if it drops below the level that calculation supports.
>
> **What did NOT change, because it is the half that matters.** The mechanism requirement is
> untouched and enforced mechanically: structural §48 requires every skill's **selftest** to drive
> its committed *partial* reference to strong through a revision round with a positive delta. So
> *"a pass/fail check wearing a loop's clothes"* is excluded by construction for all five skills,
> independently of anything a model does. What the amendment changes is only how the **model's**
> need for revision is established — observed, or bounded.
>
> **The disclosure that belongs next to it: this amendment makes all five skills pass.** It was
> directed after the results were known, which is the exact shape of a bar moved to fit its data.
> Two things argue against that reading and neither is conclusive — the threshold is derived from a
> stated calculation that references nothing measured, and the pre-amendment verdict (**3 of 5**) is
> preserved above rather than overwritten. **The decision was the operator's, on the record.** Under
> this repo's separation of duties that is where a gate decision belongs: the author declined to
> move the bar, because §7.1 forbids changing a bar after seeing which subjects fail it.

**A zero is a bound, not a proof.** `0/13` says the rate is below roughly 21%; it does not say the
skill never revises. Read the rates, not the verdicts — current figures in
[`evals/DAY1-REPORT.md`](../../../evals/DAY1-REPORT.md).

## §2. The instrument

Built and mutation-tested before any phase was measured: an `oracle` detector kind; `detector.rows`
to score the *fraction* of an oracle's rows that pass (without it a five-row contract scores 0 or 1
and the delta has two reachable values); `grades: "workspace"` so the draft is a directory;
carry-forward, so the revision round starts from the previous round's deliverable in a fresh
directory; and `--report`, which derives `evals/DAY1-REPORT.md` from the baseline.

Then the four things P2–P5 needed on top, none of them a scoring choice: directory seeds and
multi-path deliverables (a flattened seed lands where the oracle does not look, and **every artifact
scores 0 while the instrument reports itself healthy**); two row renderers that import the real
scripts rather than re-implementing a rule; a real per-round cost capture; and **vacuity guards**,
because a lint reports nothing for an artifact that is not there. Every profile fails all of its
rows when its subject is absent, and §48(d1b) asserts a seed-only workspace scores exactly `0`.

> **Not hypothetical.** The first wiring renderer excluded unresolvable engines from the
> reachability row. On a paid run that scored a map **5 of 6 green while six of six engines had
> never been resolved at all**. **A green row whose evidence describes nothing is the shape to look
> for.**

**Still deliberately NOT built:** a model-judge head for Tier 1. It would re-introduce the judgement
this tier exists to remove.

## §3. The shared fixture spine

One seed, exercised by four skills **in pipeline order** — the order a real run uses.

```
idea.md ──▶ ba-pitch-analyzer ──▶ spec tree + board
                                      ├──▶ solution-architect ──▶ wiring-map.md
                                      └──▶ scope-architect ────▶ scopes/*.md
                                                    └──▶ task-executor ──▶ code
                                                                └──▶ spec-evaluator ──▶ verdict
```

**Risk:** a shared spine correlates the measurements. **Mitigation:** every stage after the first
runs against a **frozen committed reference input**, not the previous stage's live output. The
pipeline is the *fixture's* shape, not the measurement's dependency graph.

## §4. The phases, and what they cost

All on `claude-sonnet-5`. Spend is **measured**, from the CLI's own `total_cost_usd`.

| Phase | Work | Spend | Outcome |
|---|---|---|---|
| P0 | capture real per-run cost | none | every figure below became checkable |
| P1 | `task-executor` un-confound + re-measure | **$0.61** (est. ~$21) | confound confirmed and removed |
| P2–P5 | the four remaining rubrics + harder fixtures | **$11.77** | two ceilings **not** broken; both published |
| **P7** | **the held-out confirmatory test** — two pre-registered fixtures + a full re-measure | **$13.43** | **both predictions FAILED**, which is the result. Side-catch: **HD-005** |
| P8 | raise `n` 3 → 10 on the four skills that showed no revision | **$47.92** (est. $33) | the flicker resolved; the flicker was the finding |

**P7 is the phase to understand.** It pre-registered, in git, the prediction that both ceilinged
skills would revise once their fixtures stopped *instructing* the very check the external-fact row
measures. Both predictions failed, 3/3, and the stored artifacts show why: **these two skills go and
check.** A skill that checks is a result about the skill, not a fixture that failed.

**P8 overran its estimate structurally, not randomly.** The estimate multiplied per-run cost at n=3
by ten, which assumes runs are independent draws of equal cost. They are not: `scope-architect`
moved **444,721** output tokens at n=10 against ~78,512 at n=3 — five times the tokens for 3.3 times
the runs — because one run needed four rounds and a round's cost is dominated by re-reading the
session preamble. **The right unit for a budget is rounds × runs, not runs**, and the runs that make
a measurement worth taking are precisely the multi-round ones that break the estimate.

## §5. The finding — three dials, and only one of them is the dial

The plan assumed headroom was a difficulty setting. It is not.

| Dial | What was varied | Moved the ceiling? |
|---|---|---|
| **1 — complexity** | 6 contract rows → 12 with batch selectors; a second planted bug | **no** |
| **2 — volume** | 9 tasks/8 edges → 20/36; 17 files/8 tasks → 36/20 against a five-way split cap | **no** |
| **3 — external fact** | the artifact must agree with something the model has to **go and check** | **three of five** |

The tempting summary of dials 1 and 2 is *"the fixtures were too easy,"* and it is wrong twice over.
Every fixture ships a committed **partial** reference scoring strictly between its weak and strong
ones, and the escalations demonstrably landed — one first draft computed a 27-edge `unlocks` inverse
map correctly, another produced seven cap-compliant disjoint scopes covering twenty tasks. The
models simply do not produce the weak draft.

**What dial 3 changes is not how hard the task is, but where the answer lives.** Every ceilinged row
was graded against inputs the skill could read; the rows that have ever revised are graded against a
fact sitting outside the artifact.

> **The rule, now tested rather than fitted:** dial 3 produces headroom where checking the external
> fact is **optional to producing a plausible artifact** *and the model actually skips it*.
> `spec-evaluator` and `task-executor` do not skip it. §P7 staked the opposite outcome in a git
> commit and lost.

**Headroom is a property of task *and model* jointly** — raising difficulty against a model that can
do the task only raises the bar it clears first try.

**And the better return: five production defects, one family.** All five are the committed contract
format failing silent, and all five surfaced because a real worker wrote a real committed artifact
and a real gate read it. HD-001 made the reachability gate fail **open**; HD-005 made the same gate
fail **closed**; HD-003/HD-004 revealed the repo had **two hand-rolled parsers for one documented
format**, so fixing the first left the second silently returning empty and cost a full paid
measurement. All five are fixed and pinned — §46(f)(g)(h)(i) for the parser, §23 for the two call
sites §46 cannot reach.

**The loop cost the harness three withdrawn numbers before it found them.** Every one of those
defects first showed up as a *skill* scoring badly. Each was caught by re-scoring the stored drafts
after the fix. **Storing every artifact is what made that recoverable**, and it is the §VI.A
requirement that earns its keep most quietly.

## §6. What this does not cover, and why

**Tier 3 — six skills that document their own lack of ground truth.** `qa-edge-hunter` *"never
issues a verdict"*; `scope-hammer` compares *"never against a perfect ideal"*; `coach` files rules
*"after asking the PO to categorize each one — never assumed"*. Plus `advisor-protocol`, `shapeup`,
`orient`. Forcing a Day-1 number onto these means inventing ground truth their authors deliberately
declined to define. §VIII.A.1: *"Can success be verified? If not, do not begin with autonomy."*

**`tech-lead` — right rung, wrong measurement.** Its output is a *run*, not an artifact; you cannot
revise a run, only start another. It belongs at Table III's workflow layer.

**The honest ceiling is 6 of 13** (5 Tier-1 + `translator`), not 13/13. Five are instrumented and
measured — the whole of Tier 1. `translator` is the one remaining skill inside that ceiling.

## §7. Risks

1. **The oracle becomes the target.** Optimising a skill to satisfy `spec-lint` is not the same as
   good slicing. **Mitigation — the no-retuning rule:** the oracles were written before this
   measurement existed and are **not to be relaxed to raise a score.** Where a fixture must change,
   the change is declared before the run and both numbers are published.
2. **The apparatus becomes the target.** Phase 1's actual failure, and the more insidious one,
   because it survives full oracle delegation. Mitigated by §0's derivability audit, run *before*
   each measurement. **It came up again in P3 and the audit ruled against the change** — the
   heading was stated in the fixture prompt and the bare path in the skill's own contract, so the
   fixture was not touched. The rule earns its keep by ruling *against* a change as often as for one.
2b. **The instrument's own vacuous truth** — a lint reports nothing for an artifact that is not
   there. Every renderer now fails all its rows when its subject is absent (§2).
3. **Correlated fixtures.** One spine grounds five measurements. Mitigated by frozen reference
   inputs per stage (§3), not eliminated.
4. **Structural conformance read as quality.** Two of the five can only measure well-formedness. The
   caveat rides in `per_skill_notes`, which §48 forces into the report.
5. **Cost overrun on code generation.** *Did not materialise, and the reason inverts the risk* —
   `task-executor` was the **cheapest** of the five. What drives spend is the per-round cache-read
   of the session preamble, so the correct lever is *rounds × runs*, not turn cap or output length.
