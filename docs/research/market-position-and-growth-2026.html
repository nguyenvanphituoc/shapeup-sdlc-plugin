3 · Strategy

Which fight to pick

✕ Compete as “another SDD framework”

Head-on against spec-kit (124k, Microsoft-backed, 35 integrations, 138 extensions), OpenSpec (62k) and BMAD (51k). Saturated at the top, and the differentiator you would be selling — rigor — is what every entrant claims. New entrants in this lane land around 3k after twelve months of work (cc-sdd).

✓ Own two uncontested positions

1. The Shape Up harness for coding agents. Ceiling 1,404 ★, and that project is shaping-only. This is the only harness carrying Shape Up's building apparatus — appetite, betting table, hill charts, scope hammer, “QA is for the edges”, baseline-not-ideal — into a mechanized loop.

2. The verification layer that stops agents lying about done. Everyone else's answer to this is prose; Superpowers' actual technique is rhetorical persuasion. Yours is a hook that denies the dispatch.

Shape Up for coding agents — with gates the agent can't talk its way past.

One line, used identically in the repo description, the README H1 and the Show HN title.

5 · Architecture read

The enforcement axis — why three cells look alien

How these three are framed decides whether a first-time reader thinks “obviously right” or “over-engineered”. Today it reads as the second.

5.1 · One idea, not three features

All three are the same move: take an invariant out of the prompt and put it in the runtime.

InvariantWhere the field keeps itWhere this repo keeps it
A worker receives well-formed contextprose in a markdown fileJSON Schema + a hook that denies
Shared state does not get corruptedagent discipline / conventionone writer function
Phases happen in order“please don't skip EVAL”deny on the tool call

None of this is novel computing — it is ports-and-adapters, a single-writer log and a reference monitor. It is novel in this category, where the state of the art is a firmer instruction: Superpowers' actual anti-skip technique is Cialdini persuasion principles. The framing that follows:

Everyone else shipped a prompt pack. This project shipped a control plane.

The column looks alien because it is not a better answer to their question — it answers a different question.

5.2 · Why nobody else does it — and why that is good news

The field's bet: intent capture

spec-kit, OpenSpec, BMAD — get the spec right and the agent will mostly comply.

This project's bet: compliance

The spec is fine; the agent lies about what it did.

The published evidence supports both — “the spec improved the hit rate, but it did not guarantee compliance.” Spec-first raises the floor; enforcement raises the ceiling. They are complements, not substitutes. Which is the strategic payoff: this project sits on an orthogonal axis, so composition beats competition. A spec-kit user does not have to abandon spec-kit to want a hook that denies a premature EVAL. Competing with a 124k-star project is a fight; being the layer underneath it is a distribution channel. That is the justification for P2-2, re-ranked in §9 as the highest-ceiling item in the list.

5.3 · The asymmetry — one is a product, two are plumbing

The comparison table presents all three as wins. They are not the same kind of thing. Bars show each mechanism scored 0–5 on two independent jobs; the legend carries identity and every value is directly labelled.

Value to the user — marketing, demoability

Value to the system — engineering

Small multiples on a shared −3…+5 scale, diverging from a zero baseline. Scores are a considered judgement, not a measurement. Negative user value means the mechanism currently costs adoption: users meet the envelope as vocabulary before they meet a benefit.

▸ Table view

Users experience the deny hook. They never experience single-writer state — they experience the absence of corruption bugs they never knew were coming. And they experience the envelope as vocabulary they must learn before they are permitted to understand the README. Consequence: lead with enforcement, and let the other two be the reason enforcement is trustworthy — mentioned once, not as three co-equal headline features. Today AGENTS.md opens on the envelope. That is leading with the plumbing.

5.4 · The costs, stated plainly

ChoiceCost
Typed envelopeAn extensibility tax. Adding a skill to Superpowers is dropping a markdown file; adding a worker here means learning a schema. spec-kit has 138 community extensions; this project's extension cost is “read domain.schema.json”. Compounds with bus-factor 1 (G10).
Single writerA contribution bottleneck. Every new class of shared fact routes through ingest-result.mjs — i.e. through one person. It also resists piecemeal use: you cannot run just the evaluator, because state application lives in the orchestrator. dwarves-kit's bash lib/board/board.sh --help working with zero install is a real advantage traded away.
Deny hooksThe least portable of the three. Hooks are per-CLI, so the strongest differentiator does not travel to the Cursor / Codex / Antigravity targets (G7). Every false-deny is a rage-quit, and 7 PreToolUse hooks is a security-review surface — which is why SECURITY.md (P1-6) protects the headline feature rather than being hygiene.

One correction to §4's framing. Single-writer is partly a solution to a problem this project chose to have. The others get write-safety free by being single-threaded; this harness needs it because it parallelises scopes. It remains a genuine win against compaction/resume corruption — which is universal — but stated as a bare axis it flatters this repo, and a sharp reader will notice.

5.5 · Where “alien” turns into a liability

Differentiation without a named failure reads as over-engineering. When one column says “typed JSON envelope, schema-validated, hook-denied” and the rest say “markdown,” the skeptic's first thought is not “impressive” — it is “why would that need all that?” Each cell needs its failure welded on:

MechanismThe failure it prevents
Typed envelopea worker got a truncated task list after a compaction and silently built half the feature
Single writertwo parallel executors both rewrote the board; one's completions vanished
Deny hookthe agent ran EVAL on a half-green board and reported PASS

With the story attached, “alien” becomes “obvious in hindsight”. This is a README-and-table fix, not an architecture fix — filed as P0-7.

5.6 · Verdict, and which mechanism ages well

Gate enforcement and single-writer: right, keep, defend. The typed envelope: right in principle, priced wrong — it should be an invisible implementation detail, not a concept a user must learn. The acceptance test: can someone use this harness productively without ever hearing the word “WorkOrder”? Today, no. That should be yes.

The envelope erodes

It encodes the assumption “workers are unreliable at reconstructing context.” Models keep getting better at exactly that, so the assumption weakens over time.

The deny hook does not

It encodes “a model asked to report on its own work is motivated to claim success.” That is about incentives, not capability — it does not erode at all.

The moat is the enforcement layer. The envelope is plumbing that makes it trustworthy. Market accordingly.

6 · Assets

Eight real edges over the 100k-star field

Each is a mechanism the leaders do not have, not a claim about quality — and each is stated with the failure it prevents. An edge without a named failure reads as over-engineering, which is exactly how the first three currently land (§5.5).

Non-self-reported progress · the headline

Hill phase derived only from T0/T1/seesaw facts, and a hook that denies the EVAL dispatch on a non-green board.
Prevents: the agent running EVAL on a half-green board and reporting PASS.

Mechanically-enforced worker contract

WorkOrder in / WorkResult out, JSON-Schema validated, with a hook that denies a malformed dispatch before a worker runs.
Prevents: a worker getting a truncated task list after a compaction and silently building half the feature.

Single-writer shared state

One script performs every board / ledger / verdict write, structurally eliminating the state-corruption class that plagues multi-agent SDD tools.
Prevents: two parallel executors both rewriting the board, and one's completions vanishing.

Substrate sandbox

Per-scope write whitelist enforced by hook plus a disjointness lint — real parallel safety, not an annotation convention.

Two-level circuit breaker

Round budget nests an attempt budget, and an exhausted scope queues a cut proposal rather than blocking the round. Nobody else bounds retries at two granularities.

Traceability spine

Covers-closure and wiring reachability catch “feature built but never wired to the entry point”. A real, frequent pain with no competing solution in the top ten.

Single judge, EVAL once per round

A token-cost discipline that answers the “BMAD costs $2,000/mo/dev” objection head-on — if it were ever marketed.

Honest evals

Trigger evals with cross-skill hard negatives that ship status: "unmeasured", and a CI test that fails if fabricated results appear. Rare, and marketable in itself.

11 · Risks

Five honest ones

  • Complexity is the real product risk, not marketing. 13 skills, 8 gates, 3,112 lines of SKILL.md, 7 hooks. The market's stated preference in 2026 is lighter — OpenSpec at 62k on minimalism versus BMAD at 51k on maximalism. P1-2 is not a nice-to-have; without it the harness is legible only to the person who built it.
  • Attribution risk. The Shape Up wedge depends on 37signals goodwill. The existing credit to rjs/shaping-skills and Basecamp is correct and prominent — keep it that way, and reach out before launching.
  • A launch on an unfinished quickstart burns the one shot. Do not fire P2-3 until P0 and P1-1/2/5 are shipped and verified by someone who did not build it.
  • The trigger-eval integrity is an asset — do not spend it. Publishing a mediocre-but-real activation number will do more for credibility than a great fake one.
  • The envelope's extensibility tax is the quietest risk of the five (§5.4). A control plane that only its author can extend cannot accumulate contributors, and contributors are how every Tier A/B project in §2 got there. If the envelope stays a documented, user-facing concept rather than an internal detail, the ceiling is however much one person can build.

Bottom line. 500 stars is achievable inside a quarter. The binding constraint was P0-1, which took ten minutes and is done; as of 2026-07-26 it is P0-6 → P2-3 — five submissions and one launch post, none of which a build round can substitute for. Stars are still 1, and will stay 1 until something is sent.
